# Simorgh — игровой туннель

[English](README.md) · [فارسی](README.fa.md) · [中文](README.zh.md) · **Русский**

Simorgh — самостоятельно размещаемый туннель с низкой задержкой, созданный для
передачи игрового (и обычного VPN) трафика между сервером в Иране и сервером за
рубежом: снижает пинг и восстанавливает потерянные пакеты, не добавляя лишних
круговых задержек.

Ядро туннеля работает из образа, который **вы собираете сами**. Никакой образ
туннеля никогда не скачивается из реестров: `core/` — это полный исходный код на
Go, а `install.sh` выполняет по нему `docker build`.

## Панель

`panel/` — полноценная панель управления: 18 протоколов (Xray/VMess/VLESS/Trojan,
WireGuard, OpenVPN, L2TP, PPTP, IPsec/IKEv2, SSTP, OpenConnect, MTProto,
AmneziaWG, GRE, SSH, RADIUS и другие), подписки и система реселлеров с учётом
трафикового баланса. Интерфейс на 13 языках.

Помимо унаследованного от upstream, этот форк добавляет:

| | |
|---|---|
| **Мультинода** | Одна панель управляет серверами в других странах через mTLS. Для добавления нужны только IP и пароль SSH; зависимости ставятся сами, включая модули ядра. См. [docs/NODES.md](docs/NODES.md). |
| **Мультилокационные подписки** | Один инбаунд, размещённый на трёх нодах, даёт клиенту три конфигурации на выбор — все на одной квоте. |
| **Одна квота на клиента** | 20 ГБ на все его протоколы сразу, а не по 20 ГБ на каждый. |
| **Лимит устройств** | Ограничивает, сколько устройств могут получить подписку. Прочитайте раздел об области применения в [docs/RESELLERS-AND-DEVICES.md](docs/RESELLERS-AND-DEVICES.md), прежде чем продавать это как функцию. |
| **Отдельная панель реселлера** | Реселлеры входят по своему URL, поэтому адрес админ-панели не известен каждому продавцу. |
| **Туннель из панели** | `core/` работает как обычное управляемое ядро рядом с Xray, с теми же запуском, остановкой и логами. Docker не требуется. |

**Настраиваете Иран → заграница?** [docs/SETUP-IRAN-RELAY.md](docs/SETUP-IRAN-RELAY.md)
проводит по шагам, включая две настройки, в которых чаще всего ошибаются.

## Быстрая установка

```bash
curl -fsSL https://raw.githubusercontent.com/devprogrmer/simorgh/main/install.sh -o /tmp/simorgh-install.sh && sudo bash /tmp/simorgh-install.sh
```

Сначала скачивает файл, потом выполняет — безопаснее, чем передавать напрямую в
bash. Запустите на **обоих** серверах. Скрипт сначала спросит, для чего этот
сервер, и дальше настроит всё сам.

## Что внутри

- **Транспорты**: ICMP (по умолчанию — наименьшие накладные расходы и меньше
  всего шансов быть отфильтрованным), UDP или `auto` (только на стороне клиента:
  пробует ICMP, затем UDP, и фиксируется на том, что дошло). Всё
  двухстековое — IPv4 и IPv6.
- **Перенос любого протокола**: `MODE=forward` передаёт трафик на базе UDP
  (WireGuard, OpenVPN-UDP, L2TP/IPSec) или TCP (OpenVPN-TCP, Cisco,
  Xray/VLESS-TCP, Trojan).
- **Много клиентов на одном сервере**: `CUSTOMERS_FILE` обслуживает несколько
  клиентов одним процессом, каждый полностью изолирован — своя криптография,
  свой FEC и необязательный предел полосы.
- **Безопасность**: рукопожатие X25519 для прямой секретности и шифрование
  сессии AES-256-GCM. Пароль аутентифицирует рукопожатие и никогда не является
  ключом шифрования напрямую; для каждой сессии согласуется новый ключ.
- **Адаптивный FEC**, **автопереключение между серверами** (по RTT и потерям, с
  гистерезисом), **живой мониторинг качества канала**, **оптимизатор MTU**,
  **маркировка DSCP**, **шейпинг полосы**.

## Требования

- Linux-VPS в Иране и Linux-VPS за рубежом, оба под вашим контролем, с открытым
  между ними ICMP или UDP-портом.
- Docker (`install.sh` установит его сам, если его нет).
- Root-доступ на обеих машинах.

## Состояние тестирования — прочитайте, прежде чем доверять вслепую

Этот раздел намеренно прямолинеен: документация, которая не говорит, что осталось
непроверенным, хуже, чем её отсутствие.

- **Ядро туннеля** (оба транспорта, оба режима, переключение серверов,
  ретрансляция TCP и UDP, изоляция клиентов): проверено сквозными тестами на
  реальных сетевых пространствах имён. IPv6 просмотрен по коду, но **не
  проверялся в работе** — проверьте на своём сервере.
- **Панель**: собирается, весь набор тестов зелёный. Но **мультинода не
  запускалась на реальном сервере** — загрузка по SSH, удалённая установка
  зависимостей и туннель под настоящей нагрузкой покрыты только модульными
  тестами.
- **Общая квота**: один email на двух **нативных для Xray** инбаундах не
  проверялся на живом Xray. Остальных протоколов это не касается.
