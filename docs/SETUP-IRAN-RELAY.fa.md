# راه‌اندازی: رله‌ی ایران به یک یا چند سرور خارج

رایج‌ترین توپولوژی، و همانی که بیشتر مردم موقع راه‌اندازی منظورشان است:

```
مشتری (تهران) ← سرور ایران ← تانل سیمرغ ← سرور خارج ← اینترنت
```

مشتری به یک آدرس ایرانی وصل می‌شود. آن اولین hop محلی و سریع است، و کل دلیل بودن
سرور ایران در مسیر همین است. تانل ترافیکش را به خارج می‌برد.

اگر به‌جایش می‌خواهید مشتری **مستقیم** به هر سرور خارج وصل شود و در اپلیکیشنش
کشور را انتخاب کند، توپولوژی مستقیم را می‌خواهید — به
[مولتی‌لوکیشن مستقیم](#مولتی‌لوکیشن-مستقیم) در انتها بروید.

## چه چیزی کجا اجرا می‌شود

| | سرور ایران | سرور(های) خارج |
|---|---|---|
| پنل | بله | نه |
| تانل سیمرغ | client | server |
| دیمن واقعی VPN (WireGuard، OpenVPN…) | نه | بله |
| نود پنل | اختیاری | اختیاری |

دیمن VPN **در خارج** اجرا می‌شود. سرور ایران فقط رله می‌کند. حالت forward دقیقاً
برای همین است.

## ۱. سرور خارج — تانل server

در پنل: **Settings ← Tunnel**.

| تنظیم | مقدار |
|---|---|
| Mode | `forward` |
| Operating mode | `server` |
| Password | هر چیز طولانی؛ باید دقیقاً با سمت ایران یکی باشد |
| Transport | `icmp` |
| Target host | `127.0.0.1` |
| Target port | پورت دیمن واقعی، مثلاً `51820` برای WireGuard |

بعد خود دیمن VPN را روی همین ماشین مثل همیشه راه بیندازید — روی localhost گوش
می‌دهد و هیچ‌وقت مستقیم رو به اینترنت نیست.

## ۲. سرور ایران — تانل client

| تنظیم | مقدار |
|---|---|
| Mode | `forward` |
| Operating mode | `client` |
| Password | همان رمز |
| Transport | `icmp` |
| Remote IP | همه‌ی سرورهای خارج، با کاما |
| **Forward bind** | **`0.0.0.0`** |
| Local port | چیزی که مشتری به آن وصل می‌شود، مثلاً `51820` |

### Forward bind همان جایی است که همه گیر می‌کنند

پیش‌فرضش `127.0.0.1` است، یعنی تانل فقط از خود سرور ایران در دسترس است. هر اتصال
مشتری رد می‌شود و **هیچ چیزی در لاگ نمی‌گوید چرا** — چون از دید تانل اصلاً چیزی
نرسیده. حتماً روی `0.0.0.0` بگذارید.

### چند سرور خارج

همه را در Remote IP با کاما بدهید:

```
203.0.113.10,198.51.100.7,192.0.2.44
```

هسته مدام RTT و packet loss واقعی هر کدام را می‌سنجد و به بهترینشان می‌رود، با
hysteresis تا مدام بالا و پایین نپرد. **این همان failover است** — سوییچ جداگانه‌ای
برای روشن کردن ندارد و انتخاب دستی لازم نیست.

## ۳. آدرس ایران را به مشتری بدهید

این قدمی است که به‌راحتی اشتباه می‌شود، و اشتباه شدنش بی‌صدا همه‌ی کارهای بالا را
دور می‌زند.

دیمن VPN در خارج اجرا می‌شود، پس پنل آن را روی نود خارج مدیریت می‌کند. ولی مشتری
باید به **ایران** وصل شود. اگر کانفیگش آدرس سرور خارج را داشته باشد، ترافیکش
مستقیم به آنجا می‌رود و سرور ایران — که کل دلیل پینگ پایین است — اصلاً استفاده
نمی‌شود.

پس روی placement، فیلد **Advertise** را روی آدرس عمومی سرور ایران بگذارید.

- **Listen** — جایی که دیمن bind می‌شود، روی ماشینی که اجرا می‌شود.
- **Advertise** — چیزی که در کانفیگ مشتری نوشته می‌شود. برای اتصال مستقیم خالی
  بگذارید؛ وقتی رله جلویش هست پرش کنید.

با Advertise تنظیم‌شده، ساب آدرس ایران را به مشتری می‌دهد در حالی که پنل همچنان
دیمن را در خارج مدیریت می‌کند.

## ۴. امتحانش کنید

۱. از سیستم خودتان با ساب یک کلاینت وصل کنید.
۲. مطمئن شوید endpoint کانفیگ آدرس **ایران** است.
۳. مطمئن شوید آی‌پی خروجی، آی‌پی **سرور خارج** است.

اگر endpoint درست بود ولی آی‌پی خروجی ایران بود، تانل ترافیک را نمی‌برد —
Forward bind و یکی بودن رمز دو طرف را چک کنید. اگر اصلاً وصل نمی‌شوید، transport
را از `icmp` به `udp` عوض کنید؛ بعضی مسیرها ICMP را کامل می‌اندازند.

## آیا سرورهای خارج باید نود باشند؟

**نه — برای این توپولوژی لازم نیست.** ترافیک از طریق تانل به آن‌ها می‌رسد، چه پنل
بشناسدشان چه نه.

نود کردنشان مدیریت از راه دور می‌دهد: وضعیت، لاگ هر هسته، و نصب خودکار پیش‌نیازها
از پنل به‌جای SSH. این واقعاً مفید است، ولی راحتی است نه اتصال.

یک وابستگی هم اضافه می‌کند که ارزش فهمیدن دارد. پنل هر نود را روی پورت API‌اش
(پیش‌فرض 62050) صدا می‌زند — یک اتصال خروجی از ایران به یک پورت غیرمعمول، که
دقیقاً همان چیزی است که ممکن است فیلتر شود. اگر آن کانال بسته شود، نود **آفلاین**
نشان داده می‌شود و دیگر نمی‌توانید از پنل مدیریتش کنید، ولی **ترافیک مشتری قطع
نمی‌شود**: آفلاین یعنی کانال کنترل، نه مسیر داده، و دیمن‌ها همان چیزی را که آخرین
بار داشتند ادامه می‌دهند.

**اول تانل را بدون نود راه بیندازید.** بعد اگر مدیریت از راه دور خواستید اضافه
کنید. اگر معلوم شد کانال کنترل فیلتر است، چیزی از دست نداده‌اید.

## مولتی‌لوکیشن مستقیم

اگر ترجیح می‌دهید مشتری مستقیم به هر سرور خارج وصل شود:

- inbound را روی هر نود خارج بگذارید.
- **Advertise** را خالی بگذارید تا هر کانفیگ آدرس نود خودش را بگوید.
- تانل لازم نیست.

آن‌وقت ساب به ازای هر لوکیشن یک کانفیگ دارد، با نام نود برچسب خورده، و مشتری
انتخاب می‌کند. همه‌شان از یک سهمیه‌ی واحد روی اکانتش کم می‌کنند.

پینگ بالاتر از رله، ولی سرور ایرانی در مسیر نیست که خراب شود، و چیزی بین مشتری و
خروجی نیست که فیلتر شود.
