# سیمرغ — تانل گیمینگ

[English](README.md) · **فارسی** · [中文](README.zh.md) · [Русский](README.ru.md)

سیمرغ یک تانل کم‌تأخیر و self-hosted است که برای عبور دادن ترافیک بازی (و VPN
عمومی) بین یک سرور ایران و یک سرور خارج ساخته شده — پینگ را کم می‌کند و از دست
رفتن پکت را جبران می‌کند بدون اینکه رفت‌وبرگشت اضافه بیندازد.

هسته‌ی تانل از ایمیجی می‌آید که **خودتان بیلد می‌کنید**. هیچ ایمیج تانلی از هیچ
رجیستری کشیده نمی‌شود — `core/` سورس کامل Go است و `install.sh` رویش
`docker build` می‌زند.

## پنل

`panel/` یک پنل مدیریت کامل است — ۱۸ پروتکل (Xray/VMess/VLESS/Trojan، WireGuard،
OpenVPN، L2TP، PPTP، IPsec/IKEv2، SSTP، OpenConnect، MTProto، AmneziaWG، GRE،
SSH، RADIUS و بیشتر)، ساب‌سکریپشن، و سیستم ریسلر با دفتر حساب حجمی. رابط کاربری
به ۱۳ زبان.

علاوه بر آنچه از آپ‌استریم به ارث برده، این فورک این‌ها را اضافه می‌کند:

| | |
|---|---|
| **مولتی‌نود** | یک پنل، سرورهایی در کشورهای دیگر را با mTLS می‌گرداند. افزودن نود فقط یک آی‌پی و رمز SSH می‌خواهد؛ پیش‌نیازها خودشان نصب می‌شوند، حتی ماژول کرنل. → [docs/NODES.fa.md](docs/NODES.fa.md) |
| **ساب مولتی‌لوکیشن** | یک inbound روی سه نود، سه کانفیگ به مشتری می‌دهد که بینشان انتخاب کند — همه از یک سهمیه. |
| **یک سهمیه برای هر مشتری** | ۲۰ گیگ روی همه‌ی پروتکل‌هایی که دارد، نه ۲۰ گیگ برای هرکدام. |
| **محدودیت دستگاه** | تعیین می‌کند چند دستگاه بتوانند ساب را بگیرند. قبل از فروش روی آن، بخش محدوده در [docs/RESELLERS-AND-DEVICES.fa.md](docs/RESELLERS-AND-DEVICES.fa.md) را بخوانید. |
| **پنل ریسلر جدا** | ریسلرها در آدرس خودشان وارد می‌شوند، پس مکان پنل ادمین چیزی نیست که هر فروشنده‌ای بداند. |
| **تانل از داخل پنل** | `core/` به‌عنوان یک هسته‌ی مدیریت‌شده کنار Xray اجرا می‌شود، با همان start/stop/logs. Docker لازم ندارد. |

**دارید ایران به خارج راه می‌اندازید؟** [docs/SETUP-IRAN-RELAY.fa.md](docs/SETUP-IRAN-RELAY.fa.md)
قدم‌به‌قدم توضیح می‌دهد، از جمله دو تنظیمی که بیشتر از همه اشتباه می‌شوند.

## نصب سریع

```bash
curl -fsSL https://raw.githubusercontent.com/devprogrmer/simorgh/main/install.sh -o /tmp/simorgh-install.sh && sudo bash /tmp/simorgh-install.sh
```

اول فایل را دانلود می‌کند بعد اجرا — امن‌تر از pipe مستقیم به bash. روی **هر دو**
سرور (ایران و خارج) اجرا کنید. اسکریپت اول می‌پرسد این سرور برای چیست و بقیه را
خودش می‌چیند.

اگر ترجیح می‌دهید اول کد را بخوانید — که قبل از اجرای هر چیزی با روت خواسته‌ی
معقولی است:

```bash
git clone https://github.com/devprogrmer/simorgh.git
cd simorgh && chmod +x install.sh && sudo ./install.sh
```

## داخلش چیست

- **ترنسپورت‌ها**: ICMP (پیش‌فرض — کمترین سربار، کمترین احتمال فیلتر)، UDP، یا
  `auto` (فقط سمت کلاینت — اول ICMP بعد UDP، روی هرکدام که برسد قفل می‌شود).
  هر دو دوپشته‌ی IPv4/IPv6.
- **حالت carrier برای هر پروتکلی**: `MODE=forward` ترافیک UDP (WireGuard،
  OpenVPN-UDP، L2TP/IPSec) یا TCP (OpenVPN-TCP، Cisco، Xray/VLESS-TCP، Trojan)
  را حمل می‌کند.
- **چندمشتری روی یک سرور**: `CUSTOMERS_FILE` چند مشتری را از یک پروسه سرو
  می‌کند، هرکدام کاملاً ایزوله با کریپتو، FEC و سقف پهنای باند خودش.
- **امنیت**: handshake با X25519 برای forward secrecy و رمزنگاری نشست با
  AES-256-GCM. رمز، handshake را احراز می‌کند و هیچ‌وقت مستقیماً کلید رمزنگاری
  نیست؛ هر نشست کلید تازه مذاکره می‌کند.
- **FEC تطبیقی**، **failover خودکار بین چند سرور** (بر اساس RTT و loss، با
  hysteresis)، **پایش زنده‌ی کیفیت لینک**، **بهینه‌ساز MTU**، **علامت‌گذاری
  DSCP**، **شکل‌دهی پهنای باند**.

## پیش‌نیازها

- یک VPS لینوکس در ایران و یک VPS لینوکس در خارج، هر دو در اختیار خودتان، با
  ICMP یا یک پورت UDP باز بینشان.
- Docker (اگر نباشد `install.sh` خودش نصب می‌کند).
- دسترسی روت روی هر دو.

## وضعیت تست — قبل از اعتماد کورکورانه بخوانید

این بخش عمداً صریح است، چون یک سند که نمی‌گوید چه چیزی تست نشده بدتر از نداشتن
سند است.

- **هسته‌ی تانل** (هر دو ترنسپورت، هر دو حالت، failover، رله‌ی TCP و UDP،
  ایزولاسیون چندمشتری): در تست‌های واقعی مبتنی بر namespace به‌صورت سرتاسری
  آزمایش شده. IPv6 بازبینی کد شده ولی **در زمان اجرا تست نشده** — روی سرور
  خودتان امتحانش کنید.
- **پنل**: کامپایل می‌شود و مجموعه تست‌هایش سبز است. ولی **مولتی‌نود روی سرور
  واقعی اجرا نشده** — bootstrap با SSH، provision از راه دور، و تانل زیر بار
  واقعی همگی فقط با تست واحد بررسی شده‌اند.
- **سهمیه‌ی مشترک**: یک ایمیل روی دو inbound **نیتیو Xray** روی Xray واقعی
  آزمایش نشده. بقیه‌ی پروتکل‌ها متأثر نیستند.
